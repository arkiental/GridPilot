# Placement interactions

Open Focus and select a window by sidebar or Ctrl-click. An ordinary grid drag places only the selected window, including over other applications. Left/Right/Fill and current-display saved presets use the same single-window path. Native minimum sizes are checked before moving; a larger stable size discovered during placement is accommodated inside the same transaction without rolling back first. Undo retains the original frame and maximized state. Ctrl-click still selects a window, while Ctrl-drag places the current selection, so holding the opening shortcut's Ctrl key cannot silently swallow a drag.

Enable **Reflow windows** to preview and move displaced windows as a group. This defaults off. Settings > General > Reflow overlapping windows controls the saved default; the Focus checkbox overrides it for the current session. The remaining occupancy rules below apply to reflow, free-space operations and swaps, not ordinary single-window placement.

When the current captured windows form an exact rectangular split with the configured gap, orange shared dividers appear in Focus without a toggle. Drag a divider to preview neighboring frame sizes, then release inside the preview to apply the group. Focus a divider to use arrows in 8 physical-pixel steps; **Divider px** accepts an exact physical coordinate, and **Apply divider** commits that preview. Escape or Cancel restores the original draft without moving windows. The selected window keeps its red marker, and the desktop screenshot stays visible below the proposed orange frames. Unsupported layouts, fixed places, locked ratios, and minimum-size conflicts do not offer a misleading movable handle. After placement, Focus refreshes its screenshot and divider geometry.

Only windows directly overlapped by the requested destination may move. Other visible windows, including unavailable or fixed-size windows, remain obstacles. If the selection covers an unavailable window, or the bounded search finds no remaining grid rectangles meeting configured minimums, nothing moves. Choose fewer cells, a finer grid, or move an obstruction first. Native application minimums may be larger or change dynamically; rejected native placements roll back with the requested and observed frame reported.

Hold Alt and drag a preview window onto another to exchange their exact positions and sizes, including unequal rectangles. When multiple source windows overlap, select the intended source with Ctrl-click first. When several destination windows overlap, turn the wheel during the drag to choose one explicitly; the destination name and complete swap preview are shown before release. A swap may preserve existing overlap between its two source rectangles; it never silently turns an arbitrary overlapping arrangement into a valid plan.

Placement retains exact HWND and PID identities and physical-pixel geometry. Before and during a guarded transaction, GridPilot rechecks destination occupancy. A newly opened/restored window or a window moving into the destination cancels the operation and restores touched windows. New windows outside the destination do not cancel it. An exact swap can retain unchanged overlaps already present in the captured preview. Legacy Auto arrange keeps its separate documented behavior for excluded windows.

Focus can remain open after placement. Escape closes it, and the title bar moves it. Its desktop image refreshes once after each operation by briefly hiding only GridPilot's panel and waiting for the compositor before capture. This is a refreshed screenshot, not continuous live main-canvas video; the sidebar retains its live DWM previews. Closing during refresh cannot reopen the panel, and refresh does not reactivate it after the user switches applications. **Fill empty slot** uses the separate partial-placement workflow when wired by the application.

Batch placement sends bounded requests and waits for stable native responses, including a delayed restore from maximized state. This resolves the reproduced one-second fixture response that exceeded the older batch retry budget; it does not establish the cause of every production app rollback. A refusing or stale window still fails safely, with grouped Undo retaining any restoration that could not be verified. Occupancy cancellation first waits for an outstanding native move to settle; original-looking bounds alone do not prove that queued work is finished. If the bounded wait expires, new placements remain blocked until Undo proves responsiveness and restores the snapshot. Recovery first tries a same-size two-pixel translation inside the work area, then slight growth, so an app already at its minimum can respond. A frame filling the work area may briefly extend or move at most two pixels beyond its original bounds before verified restoration. An app that refuses or remains busy retains its retry snapshot, including after an immediate Undo.

Validation includes core geometry tests and owned native fixtures for delayed acceptance, combined one-second/six-second resize delays with a new blocker and post-failure verification, unequal overlapping swaps, grouped Undo, stale identities/geometry, newly appearing/restored/moving blockers, irrelevant occupancy, focus preservation and cancellation during refresh. Fixtures use an injected catalog restricted to their own disposable windows; production always enumerates the real desktop. The default native suite includes these tests; `--interactions` runs them separately. Actual 8K100% ergonomics, changing app-native minimums and mixed-monitor hardware remain manual checks.
